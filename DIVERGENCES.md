- **G-468 — OPEN: mouse text-selection interaction diverges from ref.** Report: "划选逻辑仍然和 ref 不一致". Leads: multi-click cycle wraps (`count % 3`) vs ref clamp at line-select (`min(count+1, 3)`, opentui core `renderer.ts` nextClickBehavior); consecutive-click hit test requires the identical cell vs ref Chebyshev ≤1; ctrl+click extend-selection absent (ref `renderer.ts`); selection cleared on copy/release vs ref never clearing (`util/selection.ts` `copy`, `renderer.ts` `finishSelection`) — `pty_w11_mouse` currently pins the port's clearing as expected behavior and needs a justified re-pin; release swallowed vs ref dispatching the up with `isDragging:true`; manual-mode right-click copy absent (ref `app.tsx`). Lane va12 landed 6/7 deltas 2026-11-24 (merge `52598895`): multi-click capped at line (`min(count+1,3)`), consecutive-click Chebyshev ≤1 (bounded approximation documented — ref counts only presses that started a selection on a selectable renderable), ctrl+click extends a kept selection, copy/finish no longer clears (ref `renderer.ts:3807-3814` fresh non-ctrl press clears — `pty_w11_mouse` re-pinned with justification), release dispatched to targets (toast guard mirrored from `toast.tsx:59-62`; wider guard asymmetry logged below), manual-mode right-click copies. PTY 41/41, selection units 58/58, merge gate `2443/2444`. **Residue OPEN (architectural, own lane + full mouse-family regression):** selectable-renderable scope (`renderer.ts:3688-3693` `canStartSelection` / `Renderable.selectable` defaults), pressed-guard asymmetry on Up dispatch (ref guards: tabs `session-tabs.tsx:1505-1514`, rail `session-tabs-rail.tsx:38-48`, dialog backdrop `dialog.tsx:35-44` — vs the port's unguarded dispatch, drag-release onto tabs/option rows can mis-trigger), focused-editor guard (depends on the same renderable model).
- **G-469 — CLOSED 2026-11-24** (va12 `0b3df50e`, merge `52598895`): the untitled toast face renders the bottom pad row (3-row face) and the muted `x` affordance on the message line; `toast_layout` counts the aff run in the untitled width (the recon claim that it already did was wrong — lane-corrected against source); `+N more` pending margin ported for the untitled face.
