## Scope interpretation (recorded to prevent ambiguity)

- **IN**: `packages/app` (Web UI, served by `opencode serve`, PWA), all `packages/cli` commands (incl. `mini`, `acp`), packages shared by app/cli such as `session-ui`, all TUI capabilities (C2 animation-class unfrozen), full plugin-system semantics.
- **OUT**: `packages/desktop` (Tauri shell); `packages/web` (Astro marketing/docs site — not product functionality; migrate only on separate instruction); upstream features added after v2.0.24 (pinning discipline unchanged).
- `packages/gui-extensions` (SSH/WSL remote CLI management): desktop companion, excluded with the desktop app; reassess case-by-case if it contains desktop-independent capability.

## 4. Verification-system reinforcement (institutionalizing this round's blind spots)

1. **Responsive PTY test class**: terminal emulator answers OSC 11/DA for real — a TUI gate element since B3-04.
2. **Real corpus**: run engine/DB integration against a sanitized real v2 DB snapshot as read-only fixture (NULL distribution, large-DB performance).

4. **Long soak**: hours-level serve+TUI soak (memory/handles/event ordering).
5. **Dual-end differential testing spec** (promoted 2026-10-11 by user directive, **the sole adjudication standard for TUI parity**):

   > **SUPERSEDED 2026-10-17** — differential testing retired by user ruling (see change log); the scan loop replaced it as the acceptance instrument, then itself concluded at FIXW2. Golden-frame tests remain as the regression suite.

   > **Same directory, same operations, both ends running in parallel, full step-by-step equality.**

   - **Both ends in parallel**: the v2.0.24 reference TUI (rebuilt from the pinned source at `/opt/opencode-ref`) and the rust TUI each get a PTY, same size (80x24 and 120x30 initially).
   - **Same directory**: identical project cwd and seed files (git repo + filenames exactly equal); independent home/data dirs per end (DB not shareable); same stub provider, same model name, equivalent config on both ends — footer/prompts and other chrome must be comparable too.
   - **Same operations**: one shared JSON operation script (text/keys/SGR mouse/leader chords/waits), fed to both ends at the same cadence.
   - **Full step-by-step equality**: after every step, cell-level comparison (glyph + style digest). **Chrome regions (tab strip/footer/dialogs/input/sidebar) byte-identical**; per step record identical / first-divergent cell / both-end row snapshots.
   - **Structural comparison mode**: model-output regions naturally differ run-to-run, so verbatim equality is not required — normalize to markers and compare **structural geometry**: row-count/content-length relations, header-to-content distances (e.g. expanded Thought header ↔ content block spacing), margin and indent relations. The two modes are reported separately.
   - **Normalization minimized**: only registered, justified normalizations allowed (model-text normalization, unavoidable process-level differences); masking divergence with normalization is forbidden; every new normalization must be registered in the NORMALIZATION doc.
   - **Adjudication**: self-built goldens demoted to regression protection; TUI parity is decided by dual-end zero diff. Mismatches triage into three classes: deterministic bug (must fix) / reference-side timing noise (separated by re-runs) / registered legal divergence (must be argued).
   - **Entry point**: gated by `OC_TUI_DIFF=1` (skip when the reference build is missing, like OC_TUI_SMOKE); corpus includes boot, edit+submit (stub fixed reply → transcript compare), tab lifecycle, /help, palette, theme switch, thought expand (structural mode), tab +/✕ hover (SGR), resize.

## 4.5. Development discipline (structurally enforced, from 2026-10-11)

This machine and the online services (newapi, 49374) share 16 cores/22G. Past incidents: one CPU-saturating cargo build; three ownership-pollution incidents from root running cargo directly. Discipline upgraded from "written in lane prompts" to **structural enforcement**:

- **`tools/dev-gate.sh` is the single entry point for every local build/test command**: forces eternal130 identity, installs a systemd transient scope (`CPUQuota=400%` four-core hard cap + `MemoryMax=10G` + `TasksMax=512`), refuses to start at 1-minute load ≥6. Verified `cpu.max=400000 100000` in effect — no lane forgetting `-j4`, nor parallel lanes stacking, can physically saturate the machine anymore.
- CI (GitHub Actions) exempt (doesn't run on this machine).
- The remaining frozen-discipline rules stay in force: never touch 49374 or online dirs; tests always `127.0.0.1:0`; /tmp/opencode top level uses PID-unique names; no bare-PID process kills; dev tests write only to sandboxes, never to real user data dirs; DNS probes (/tmp/opencode/dns-probe.*) are not build artifacts, do not clean.
- All lane specs must state "local commands always go through `tools/dev-gate.sh`".
- **Lane write isolation (added after the 2026-10-11 second incident)**: parallel lanes each use an independent git worktree (`git worktree add`), integration merges back to main serially — sharing a single checkout dir already caused one lane's files to be deleted by another. Lanes sharing the main checkout must: commit early and often (small WIP commits, squashed later), touch only files in their own scope, re-check `git status` before the final commit.

### R-04 Web UI architecture decision (ruled after 2026-10-11 recon)

Factual basis: the rust hosting contract is fully ready (`oc-server/src/assets.rs` serveUI port: SPA fallback, `_assets|icons` 404, immutable/no-cache split, CSP+inline-script hashes, nosniff, HEAD; `auth.rs` Basic+`auth_token`+same-name port cookie; `pairing.rs` pairing; SSE event stream) — **the only gap is `state.rs`'s empty asset map**. v2.0.24 ships no standalone app artifact: the app (Solid+Vite8+PWA, `packages/app`, zero `@opencode/desktop` deps) build output is archived brotli+base64 and **embedded into the CLI at compile time**; dist is not committed and must be built from source.

Ruling (mirroring v2 semantics, adapted to our release pipeline):
1. **Build**: release workflow gains a `web-assets` job — fetch pinned reference source (anomalyco/opencode @ e7a34f09bf tarball) → `bun install` → `VITE_OPENCODE_SERVER_MODE=origin bun run build` (packages/app) → per-file brotli(q6) → archive passed between jobs. No dev-machine builds (no-local-build discipline), no dependence on any installed binary.
2. **Embed**: rust side gains `oc-server/build.rs` reading the archive (`include_bytes!` equivalent), filling the asset map at compile time; `OPENCODE_APP_ASSETS` env can point at an on-disk archive (matching v2's `OPENCODE_LOCAL` dist fallback), lazily decompressed at runtime.
3. **Consistency discipline**: the archive carries a provenance manifest (ref commit, app build-input hash); `_assets` content hashes + SW integrity checks naturally reject mixed-version deployments.
4. **Verification**: browser end-to-end smoke (serve → login screen → Basic/pairing-link login → session list/send/PTY WS); a tiny fixture asset map pins headers/CSP/fallback in-suite (no real archive needed).
5. **Size expectation**: with the ui package fonts/icons/audio, brotli'd dist is estimated at several-to-low-tens of MB, shipped inside the binary (equivalent to v2 embedding it in the bun single-file).
